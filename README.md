# ⚖️ LEGAL-BRAIN — العقل القانوني الإماراتي

منصة عربية أولاً (Arabic-first) لتوليد المستندات القانونية الإماراتية **بأسلوب المحامي نفسه**.

الفكرة ليست الإجابة عن أسئلة قانونية عامة، بل استرجاع **سوابق المستخدم الشخصية** — عقوده،
إنذاراته، لوائحه، وكالاته، تشريعاته — ثم صياغة مستند جديد بنفس نبرته وهيكله ومفرداته.

---

## ما الذي يفعله النظام

| العائلة المستندية | المصدر | جدول قاعدة المعرفة |
|---|---|---|
| تشريعات وأحكام | HTML من موقع التشريعات + PDF ممسوح (OCR) | `legal_documents` |
| مذكرات ولوائح | PDF / DOCX | `legal_drafts` |
| عقود واتفاقيات | PDF / DOCX | `legal_contracts` |
| إنذارات | PDF / DOCX | `legal_notices` |
| وكالات | PDF / DOCX | `legal_poa` |

يُقطَّع كل مستند إلى وحدات دلالية (مادة / بند / قسم / صلاحية)، تُحوَّل إلى متجهات
بعدد 1024 بُعداً بنموذج `intfloat/multilingual-e5-large`، وتُخزَّن في Supabase
(PostgreSQL + pgvector). ثم يسترجع وكيل LangGraph السوابق الأقرب دلالياً ويصوغ
المستند الجديد.

## التثبيت

```bash
# ٠. ⚠️ على Linux / Codespaces: ثبّت torch نسخة CPU أولاً
#    بدونه يسحب torch حزمة CUDA بحجم 2.74 GB لا فائدة منها بلا GPU،
#    فيفشل التثبيت بـ "No space left on device".
pip install torch --index-url https://download.pytorch.org/whl/cpu

# ١. اعتماديات بايثون — تكفي لتشغيل الخادم وخطوط الاستيعاب
pip install -r requirements.txt

# ١-ب. اختياري: واجهة Chainlit + مزوّد Groq البديل
#      (لا يحتاجها main.py — تُثبَّت عند الحاجة إليها فقط)
pip install -r requirements-optional.txt

# ٢. متغيّرات البيئة
cp .env.example .env          # ثم املأ المفاتيح الفعلية

# ٣. اعتماد Google (للاستيعاب فقط، لا يلزم لتشغيل الخادم)
#    ضع ملف مفتاح حساب الخدمة باسم credentials.json في جذر المشروع

# ٤. بناء قاعدة المعرفة — نفّذ محتوى schema.sql داخل Supabase SQL Editor

# ٥. واجهة Next.js
cd frontend
cp .env.local.example .env.local
npm install
```

> **ملاحظة:** أول تشغيل يحمّل نموذج التضمين `intfloat/multilingual-e5-large` (~2.2 GB).

## واجهة الـ API

| الطريقة | المسار | الوصف |
|---|---|---|
| `GET` | `/` | صفحة اختبار مستقلة للبثّ الحي (SSE) |
| `GET` | `/health` | فحص الصحة وجاهزية الأدوات |
| `POST` | `/generate` | توليد مستند ببثّ حيّ — تستخدمه واجهة Next.js |
| `POST` | `/chat` | محادثة بردّ JSON كامل |
| `POST` | `/revisions` | حفظ زوج (مسودّة ← نسخة المحامي) مع نسبة التعديل |
| `GET` | `/revisions/stats` | تقدّم تقليد الأسلوب: عدد الأزواج وتوزيع نسب التعديل |

كلها — عدا `/health` و`/` — تتطلّب `Authorization: Bearer <API_TOKEN>` عند
ضبط الرمز.

**عقد البثّ (SSE) من `/generate`:**

```
data: {"type": "stage", "stage": "intake", "message": "جاري تحليل الطلب..."}
data: {"type": "stage", "stage": "legislation", "message": "جاري البحث في التشريعات..."}
data: {"type": "stage", "stage": "evidence", "message": "تم استرجاع السند..."}
data: {"type": "stage", "stage": "drafting", "message": "الفريق يصوغ المستند..."}
data: {"type": "stage", "stage": "verifying", "message": "مدقّق الأسانيد يراجع..."}
data: {"type": "citations", "report": {"summary": "...", "verified": [...]}}
data: {"type": "done",  "document": "إنذار قانوني\n\nالسيد/ ..."}
data: {"type": "error", "message": "..."}
```

**ولكل مرحلة حقلان:** `stage` مفتاح آلي ثابت، و`message` نصّ عربي يُعرض.
والفصل مقصود: الواجهة تقرّر **بالمفتاح** وتعرض **النصّ**. ولو رُبطت بالنصّ
لانكسر **مشهد المكتب** بصمت عند أول تعديل صياغة.

المفاتيح: `intake` · `evidence` · `drafting` · `verifying` · ومفاتيح الأدوات
الخمس: `legislation` و`drafts` و`contracts` و`notices` و`poa`.

مثال:

```bash
curl -N -X POST http://localhost:8000/generate \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"مطالبة مالية 20,000 درهم عن فواتير غير مسددة","doc_type":"لائحة دعوى تجارية"}'
```

`tests/fake_deps.py` يُسجّل وحدات وهمية في `sys.modules` **قبل** استيراد
`legal_agent`، فيُحمَّل هو **حقيقياً** — بأدواته وموجّهه ومنطقه — بينما تُستبدل

العتبة ونفس الحدّ** — وهو بالضبط ما يُسقِطه جمع الأدوات الخمس في مسار واحد.

## عقد الاستشهاد — `citations.py`

**المشكلة:** الوكيل يكتب المسودّة، ولا شيء يتحقّق أن ما فيها من مواد موجود فعلاً
في أرشيفك. فمادة مؤلَّفة تمرّ صامتة إلى مستند يُسلَّم.

**الحلّ:** النموذج **يروي**، والخادم **يُقرّر**.

1. كل مقطع مسترجع يحمل مرجعاً قصيراً (`L1` للتشريعات · `C2` للعقود · `N1` للإنذارات).
2. يُطلب من النموذج أن يُرفق **اقتباساً حرفياً** لكل سند — لا رقم مادة.
3. `citations.py` **يتحقّق حتمياً** أن كل اقتباس موجود حرفياً في نصّ المقطع
   الذي رآه النموذج.
4. ويفحص كل رقم مادة في المتن: ما لم يظهر في أي مقطع مسترجَع = **بلا سند**.

**الفائدة:** مادة مؤلَّفة لا تستطيع إنتاج اقتباس حرفي موجود في أرشيفك.

صيغة الكتلة التي يُرفقها النموذج في آخر المستند:

```
[[الأسانيد]]
L1 :: الغرامة سبعون درهماً عن كل يوم تأخير
C2 :: مدة الإخطار ثلاثون يوماً
[[/الأسانيد]]
```

ويُحذف هذه الكتلة `strip_citations_block()` قبل النسخ إلى Word، فلا يظهر في
المستند النهائي إلا المتن.

> **⚠️ حدود الفحص بصراحة:** التحقّق يمنع **التأليف**، ولا يمنع **سوء التطبيق**.
> فمادة موجودة في الأرشيف قد تكون غير منطبقة على الواقعة — وهذا حكم قانوني لا
> يحسمه كود. الفحص يجعل الأسانيد مرئية وقابلة للتتبّع، والقرار يبقى للمحامي.

### تشغيل التحقّق — جامع الأدلة

التحقّق يحتاج أن نعرف **ما أُعطي للنموذج** في هذه الجولة. وهذا ما يفعله
`collect_evidence`:

```python
from legal_agent import agent, collect_evidence, SYSTEM_PROMPT_CITED
from citations import parse_citations, verify_citations, strip_citations_block

with collect_evidence() as collected:
    final = ""
    for event in agent.stream({"messages": messages}):
        final = event["messages"][-1].content or final

parsed = parse_citations(final)
outcome = verify_citations(parsed.citations, collected.evidence)

print(outcome.summary())          # «موثَّق: 2 · مرفوض: 1 من 3.»
print(strip_citations_block(final))   # المستند نظيف للنسخ إلى Word
```

**ثلاث دقائق تصميمية في هذا المثال:**

| # | التفصيل |
|---|---|
**١** | `SYSTEM_PROMPT_CITED` لا `SYSTEM_PROMPT` — قواعد التوثيق تُضاف فقط حيث يوجد جامع يتحقّق فعلاً |
**٢** | الجامع **سياق** (`with`) لا دالّة تُستدعى وتُنسى: لو بقي مفتوحاً لتسرّبت أدلّته إلى الجولة التالية |
**٣** | `strip_citations_block` قبل العرض أو النسخ — فكتلة الأسانيد ليست جزءاً من المستند |

**⚠️ ولماذا `ContextVar` لا متغيّر عام؟** لأن `main.py` يُشغّل الوكيل في **خيط
منفصل لكل طلب**. والمتغيّر العام يخلط أدلّة الطلبات المتزامنة، فيُقبل استشهاد
مسودّة بمقطع من مسودّة أخرى — وهو خطأ يمرّ بصمت لأنه يبدو تحقّقاً ناجحاً.
وهناك اختبار مخصّص لهذا (`test_two_threads_do_not_share_evidence`).

### عقد البثّ — إطار جديد: `citations`

بعد ربط التحقّق بـ `/generate`، صار البثّ يُرسل ثلاثة أنواع من الإطارات:

```jsonc
{"type": "stage",     "message": "جاري البحث..."}
{"type": "citations", "report": { /* تقرير الأسانيد */ }}
{"type": "done",      "document": "المستند نظيفاً بلا كتلة الأسانيد"}
```

**و`citations` يصل قبل `done`** عمداً: فتكون الأسانيد جاهزة في الواجهة لحظة
عرض المستند لا بعده.

وشكل التقرير:

| الحقل | المعنى |
|---|---|
| `verified[]` | أسانيد ثبت أنها منقولة حرفياً — بالمرجع واسم المستند والاقتباس ودرجة التشابه |
| `rejected[]` | أسانيد رُفضت — **مع سببها بالعربية** |
| `unbacked_articles[]` | مواد ذُكرت في المتن ولم ترد في أي مقطع مسترجَع |
| `malformed_lines[]` | أسطر أسانيد لم تُقرأ — سند ضائع يُعرَض لا يُسقَط |
| `has_evidence` | هل نجا سند واحد على الأقل |
| `summary` | سطر عربي موجز للعرض |

> **ونقطة أمنية في الواجهة:** كل نصّ من النموذج يُعرض كمحتوى React عادي، **ولا
> `dangerouslySetInnerHTML` في المشروع**. السبب أن الاقتباسات تأتي من مخرج
> النموذج، وإدراجها كـ HTML يجعلها قابلة للحقن.

**و`/chat`** صار يُرجع الحقل `citations` مع `response` — إضافة لا كسر للعقود
السابقة، واختبار يفحصها.

### صفحة الاختبار المدمجة

`GET /` تعرض الأسانيد أيضاً: الأخضر لما ثبت، والأحمر لما رُفض بسببه،
والكهرماني لما ذُكر بلا سند. مفيدة لتشخيص التحقّق بمعزل عن واجهة Next.js.

## جمع تصحيحاتك — `revisions.py`

**المشكلة:** الهدف المُعلَن أن يكتب الوكيل **بأسلوبك**. لكن تقليد الأسلوب يحتاج
مادة خام: أزواج (ما كتبه النموذج ← ما اعتمدتَه فعلاً). وكل تصحيح في Word **يضيع**
إن لم يُسجَّل، فيبقى الأسلوب في الموجّه تخميناً لا تعلّماً.

**الحلّ:** زرّ «عدّل واحفظ نسختك» بعد كل مسودّة. يُخزَّن الزوج مع **نسبة
التعديل**، وهي مفيدة لثلاثة أمور لا لقياس الجودة وحده:

| الفائدة | التفصيل |
|---|---|
| **مؤشّر جودة فوري** | مسودّة تُعدّلها ٨٠٪ أسوأ من أخرى تُعدّلها ٥٪ — بلا استبيان ولا تخمين |
| **ترتيب الأمثلة لاحقاً** | الأكثر تعديلاً هي الأغنى بالدروس عن أسلوبك |
| **قياس تقدّم** | «٢٠٠ زوج» رقم يُتابع، بخلاف «تحسين الأسلوب» الذي لا يُقاس |

### ⚠️ وهذا الجدول ليس جزءاً من قاعدة المعرفة

**ولا عمود `embedding` فيه — عن قصد.** والسبب أهمّ من الميزة نفسها:

> المسودّة المولَّدة قد تحوي **مادة مؤلَّفة**. ولو دُمجت في الاسترجاع، لعادت في
> جولة لاحقة كـ«سياق موثوق» — **فتصير الهلوسة حقيقة مؤرشفة**. وهي أسوأ من
> الهلوسة العابرة، لأنها تترسّخ وتتكرّر.

**المبدأ: الحقيقة ما قاله المحامي، لا ما قاله النموذج.** وفيه اختبار يحمي هذا
القرار تحديداً (`test_stored_row_has_no_embedding`).

### قياسان دقيقان — وسبب كلٍّ منهما

**١) المقارنة على الكلمات لا المحارف.** «١٢٪ من الكلمات تغيّرت» مفهومة للمحامي؛
«٣٪ من المحارف» لا يعرف كيف يترجمها.

**٢) `autojunk=False` في `difflib`.** الافتراضي يعتبر الكلمات الشائعة في
المتتاليات الطويلة «نفايات» ويستبعدها من المقارنة. والنصّ القانوني العربي
**مليء** بكلمات متكرّرة («المادة»، «على»، «من»، «التي»)، فكانت النتيجة نسبة
تعديل **مضخّمة بصمت**: «تعديل ٤٠٪» على مسودّة لم تتغيّر فيها إلا كلمة واحدة.
وفيه اختبار يمنع عودة ذلك.

### وما لا يُقاس

> نسبة التعديل تقيس **الكمّ لا الجودة**. نسبة منخفضة تعني «شابه أسلوبك»، لا
> «صحيح قانوناً». وقد تكون مسودّة قريبة من أسلوبك وفيها مادة مؤلَّفة.
> فالتحقّق من الأسانيد منفصل عن هذا القياس، ولا يُغني أحدُهما عن الآخر.

### ولا تُحفظ مسودّة بلا تغيير

`build_revision` يرفض ثلاث حالات، ولكلٍّ سبب مكتوب: مسودّة فارغة، نسخة فارغة،
**وتصحيح بلا أي فرق**. والثالث مهمّ: لو حُفظ لضخّم العدّاد بلا فائدة، فأوهم
المكتب أنه جمع ٢٠٠ زوج لتقليد أسلوبه وهو لم يجمع شيئاً.

## مشهد المكتب — `frontend/components/office-scene.tsx`

أثناء الصياغة يُعرض **فريق يعمل فعلاً**: كل شخص على مكتبه، واسمه ومهمته تحته،
ولمن يعمل شاشة مضيئة وحركة وهالة، ولمن ينتظر فنجان قهوة. وبعد الانتهاء يظهر
المستند، ويُعرض تحته **من عمل عليه فعلاً**.

### ⚠️ والأهم: ليس رسوماً متحركة تجميلية

كل شخصية مرتبطة بمفتاح مرحلة **حقيقي** يبثّه الخادم. فإن لم تُستدعَ أداة
الوكالات مثلاً، **تبقى ليلى على قهوتها** — ولا يُوهم المشهد بأنها عملت.

> ولو حُرِّك المشهد بمؤقّت زمني لصار **مسرحاً يخفي ما يجري فعلاً** — وهو النمط
> المضادّ نفسه الذي رأيناه في مشروع «محاكاة التفاوض»: قيود مكتوبة في الموجّه
> ولا فحص واحد في الكود.

### الفريق — خمسة بأسمائهم في النظام

**والأسماء ليست من عندي:** هي موجودة في `smart_office.py` و`office_test.py`،
وقد اخترعتُ سابقاً تسعة أسماء فرفضها صاحب المكتب. والصحيح هو:

| المفتاح | الاسم | المهمة | المصدر |
|---|---|---|---|
| `library` | **أمين المكتبة** | البحث في الأرشيف — يستقبل الطلب ويجمع الأسانيد | `smart_office.py:68` |
| `drafter` | **مُسوَدَّة أفندي** | وكيل الصياغة | `smart_office.py:129` |
| `inspector` | **المفتش ثُغرة** | المدقق القانوني | `smart_office.py:130` |
| `polisher` | **سيبويه المُكشّر** | المدقق اللغوي | `smart_office.py:131` |
| `sealer` | **المعلم أبو الختم** | الاعتماد والختم | `office_test.py:45` |

**وثلاثة منهم نكات كاملة:** مفتش اسمه «**ثُغرة**»، وعالم نحو أسطوري اسمه
سيبويه ووجهه «**مُكشّر**» أبداً، ومن لا يُعتمد المستند إلا بـ«**ختمه**».

#### ⚠️ وهؤلاء لم يكونوا يعملون في الموقع

الأسماء في `smart_office.py` — وهو **سكربت مستقلّ لا يستدعيه `/generate`**.
فـ«المفتش ثُغرة» و«سيبويه المُكشّر» **لم يراجعا مستنداً واحداً** أنتجه الموقع.

وقد مُنحا عملاً حقيقياً في المسار الفعلي:

| من | عمله الآن | الأداة |
|---|---|---|
**المفتش ثُغرة** | التحقّق من الأسانيد | `citations.py` |
**سيبويه المُكشّر** | التدقيق اللغوي | `language_audit.py` |

**وكلاهما فحص حتمي لا نموذج** — على المبدأ نفسه: النموذج يروي والخادم يُقرّر.

### ما يفحصه سيبويه

| الفحص | الخطورة | لماذا |
|---|---|---|
مخلفات Markdown (`**` · `###` · `>`) | **خطأ** | **عيب وقع في هذا المشروع فعلاً** — ظهرت علامات حرفية في مستند مولَّد، والمستند يُنسخ إلى Word |
افتتاح حواري («بالتأكيد، إليك…») | **خطأ** | الموجّه يمنع المقدمات، وهذا عيب لا ذوق |
حقل قالب لم يُملأ (`[الاسم]` · `XXX` · `___`) | **خطأ** | مستند يخرج ومكان اسم الطرف فراغ |
كلمات لاتينية | ملاحظة | أسماء الشركات مشروعة — تُعرَض ليقرّر المحامي |
أسطر مكرّرة | ملاحظة | أثر لصق مزدوج |

> **وحدّه بصراحة:** فحص **شكلي**. يمنع عيوب الصياغة والتحرير ولا يحكم على القيمة
> القانونية. وقد يكون مستند سليم التنسيق تماماً وهو خطأ قانوناً — ولذلك هو
> منفصل عن التحقّق من الأسانيد ولا يُغني عنه.

**والأسماء استعارة لا أكثر:** لا وكلاء منفصلون في الخادم — وكيل واحد وأدوات
خمس، وأداتا فحص حتميتان. والشخصيات تمثيل بصري لمفاتيح مراحل حقيقية.

### صور الفريق (اختيارية)

المشهد يعمل بالأيقونات بلا أي صورة. وإن أردت وجوهاً مولَّدة، فالموجّهات الجاهزة
في **[agent-art-prompts.md](agent-art-prompts.md)** — تسعة موجّهات إنجليزية
بأسلوب موحّد، مع موجّه سلبي وإعدادات تقنية وطريقة «ورقة الشخصيات» التي تضمن
اتّساق التسعة.

**ولا تحتاج أي تعديل برمجي:** أَسقِط الصور في `frontend/public/agents/`
بأسماء المفاتيح (`intake.png` · `legislation.png` …) وستظهر تلقائياً. ومن لا
صورة له **يرجع إلى أيقونته بصمت**.

### واختبار يعبر حدّ اللغتين

`TestOfficeSceneContract` في `tests/test_main.py` يقرأ **ملف TSX** ويتحقّق أن:

- كل مرحلة يبثّها الخادم لها شخصية في المشهد
- ولا شخصية بمفتاح لا يبثّه الخادم

**والسبب أن العطب الذي يمنعه صامت تماماً:** لو أُضيفت مرحلة في `main.py` ولم
تُضف شخصيتها، لما ظهر خطأ — تبقى الشخصية نائمة أبداً ولا يلاحظ أحد. وهو النوع
نفسه من الانحراف الصامت الذي أصلحناه في الأدوات الخمس.

ويُفحص أيضاً أن المشهد **لا يستخدم خصائص فيزيائية** (`ml-`، `left-`) — فالتطبيق
RTL بالكامل، والخاصية الفيزيائية تُنتج الفراغ في الجهة الخطأ.


## ⚠️ الأمان

`.env` و`credentials.json` و`token.pickle` مُستثناة من git — لا ترفعها أبداً.
إن كانت `SUPABASE_KEY` هي `service_role` فهي تتجاوز RLS وتملك صلاحية كاملة على القاعدة:
لا تضعها في أي متغيّر يبدأ بـ `NEXT_PUBLIC_` ولا تُرسلها إلى المتصفح.

### قبل أي نشر عام — ثلاثة أمور إلزامية

1. **اضبط `API_TOKEN`.** بدونه `/generate` و`/chat` مفتوحان لأي زائر: يستخدم
   أرشيفك القانوني ويستهلك رصيد Gemini على حسابك. التحقق: `GET /health` يُظهر
   `"auth_required": true`.
2. **فعّل RLS** على جداول Supabase — القسم ٨ في `schema.sql` جاهز.
3. **دوّر المفاتيح** إن كانت قد ظهرت في أي لقطة شاشة أو سجل أو محادثة.

> **لماذا لا يكفي رمز في الواجهة؟** لأن أي متغيّر يبدأ بـ `NEXT_PUBLIC_`
> يُحزَّم داخل جافاسكربت المتصفح، فيقرأه أي زائر من مصدر الصفحة. ولذلك يرسل
> الوسيط `frontend/app/api/[...path]/route.ts` الرمز من جهة الخادم فقط.
